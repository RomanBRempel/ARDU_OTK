# ARDU ОТК

Настольное приложение Windows (WinUI 3, .NET 10) для серийной калибровки компаса плат
ArduPilot на цеховом стапеле. Подключается к полётному контроллеру по COM-порту (MAVLink),
прогоняет калибровочную процедуру и проверяет результат против эталона.

## Что умеет

**Подключение и телеметрия**
- Выбор COM-порта из живого списка (обновляется при подключении/отключении платы)
- Отображение крена, тангажа, рысканья, напряжения, тока и режима полёта в реальном времени
- Индикация поля каждого компаса (X/Y/Z и модуль в мГс) с оценкой нормы

**Серийная калибровка компаса**
- Фиксированная калибровка по азимуту (`MAV_CMD_FIXED_MAG_CAL_YAW`) с вводом азимута стапеля оператором
- Перенос калибровочного блока параметров с эталона на борт и независимая верификация записанного
- Приёмочные проверки: смещения (COMPASS_OFFS_MAX), модуль поля, предполётные проверки прошивки
- Принудительный перевод внешнего компаса в приоритет и выставление флагов USE/EXTERNAL
- История прогонов по каждому борту

**Эталоны**
- Хранение нескольких эталонных профилей параметров в локальной базе SQLite
- Редактор эталона: снятие снимка с платы, назначение ролей параметрам, допуски
- Проверка пригодности эталона до начала прогона

**Прочее**
- Калибровка акселерометра по уровню
- Перезагрузка борта из интерфейса
- Классификация претензий предполётной проверки (перезагрузка / калибровка / обстановка / железо)

## Модель развёртывания

Приложение **unpackaged** (без MSIX) и **self-contained**: в установщик входят и .NET, и
Windows App SDK. На цеховом ПК не требуется ничего предварительно устанавливать и не нужны
права администратора — установка идёт в `%LocalAppData%\ARDU_OTK`.

Данные (база калибровок, настройки рабочего места) хранятся в `%LocalAppData%\ARDU_OTK.Data`
и не затрагиваются при обновлении.

Обновления доставляет [Velopack](https://velopack.io) через GitHub Releases репозитория
[RomanBRempel/ARDU_OTK](https://github.com/RomanBRempel/ARDU_OTK). Репозиторий публичный,
поэтому клиентам не нужен токен.

Установщик не подписан. При первой установке Windows покажет экран SmartScreen
(«Подробнее» → «Выполнить в любом случае») — один раз на машину. Обновления после этого
идут молча.

## Выпуск новой версии

```
git tag v0.2.0
git push origin v0.2.0
```

Дальше всё делает workflow [release.yml](.github/workflows/release.yml): собирает, упаковывает
и публикует GitHub Release. Версия берётся из тега, править её в файлах не нужно —
[Directory.Build.props](Directory.Build.props) содержит только значение для локальной сборки.

Тег обязан быть вида `v1.2.3` (SemVer): по нему Velopack определяет, какая версия новее.

## Как обновляются рабочие места

Приложение проверяет обновления при старте, скачивает их в фоне и применяет с перезапуском.
Применение блокируется, пока идёт замер: см. `UpdateService.IsBusy` в
[Services/UpdateService.cs](ARDU_OTK/Services/UpdateService.cs). Код стенда должен установить
этот делегат, иначе стенд всегда считается свободным и обновление может прервать работу.

Отсутствие сети — штатная ситуация: приложение сообщает об этом и продолжает работать.

Первая загрузка около 110 МБ, последующие обновления приходят дельтами.

## Локальная сборка установщика

```powershell
dotnet publish ARDU_OTK\ARDU_OTK.csproj -c Release -r win-x64 -p:Version=0.1.0 -o publish
vpk pack --packId ARDU_OTK --packVersion 0.1.0 --packDir publish --mainExe ARDU_OTK.exe `
  --packTitle "ARDU OTK" --packAuthors ARDU --icon ARDU_OTK\Assets\AppIcon.ico --outputDir releases
```

`--packTitle` и `--icon` обязательны и здесь: без них локально собранный установщик и ярлык
получают дефолтную иконку Velopack, и локальная сборка перестаёт совпадать с релизной.

`vpk` ставится командой `dotnet tool install -g vpk --version 1.2.0`. Версия CLI обязана
совпадать с версией пакета `Velopack` в csproj.

## Если позже появится сертификат подписи

Подпись добавляется в `vpk pack` параметрами `--signParams` без изменения остальной схемы.
Это уберёт предупреждение SmartScreen. Переход на MSIX не потребуется.

## Сеть ОТК: распространение эталонов и пользователей

Точки ОТК физически не связаны. Пользователи, роли и эталоны расходятся
**пакетом сети** — одним файлом `network.otknet` в публичном репозитории
[ARDU_OTK.Network](https://github.com/RomanBRempel/ARDU_OTK.Network).
Станция скачивает его по HTTPS, как скачивает обновления. Устанавливать
ничего не нужно; ни учётная запись GitHub, ни токен станции не нужны.

- **Доверие — подпись.** Пакет подписан ключом администратора (ECDSA P-256),
  открытый ключ зашит в сборку
  ([NetworkTrust](ARDU_OTK.Shared/Network/NetworkTrust.cs)). Кто бы ни записал
  файл в репозиторий, станция примет только подписанный администратором.
- **Закрытость — код сети.** Поверх подписи пакет зашифрован AES-256-GCM кодом
  сети ([NetworkSeal](ARDU_OTK.Shared/Network/NetworkSeal.cs)): в нём эталоны
  и хеши паролей и PIN. Код сообщают станции один раз при подключении.
- **Откат невозможен.** Номер выпуска строго растёт; старый пакет станция не
  применит.
- **Новая установка** сначала открывает экран «Сеть ОТК»: код сети →
  «Подключиться». Пока пакет не принят, к стенду и эталонам не пускают. Затем
  вход по логину и паролю либо по PIN (PIN — только оператору). Станция без
  интернета принимает пакет из файла.
- **На подключённом стенде действуют только эталоны сети.** Местные уходят в
  архив, удаления нет. Местный эталон с тем же именем и теми же параметрами
  связывается с эталоном сети и сохраняет историю прогонов.
- **Эталон станции в сеть.** До подключения на экране «Сеть ОТК» есть кнопка
  «Сохранить эталоны этой станции в файлы». Администратор принимает файлы
  («Эталоны» → «Принять из файла») и выпускает пакет. Станция после
  подключения связывает свой эталон с сетевым.
- **Заводит и выводит эталоны только администратор.** Выпущенный эталон
  неизменяем; чтобы изменить, его клонируют.
- **Оператор в прогоне — вошедший пользователь**, а не текст из настроек.

Роли: `admin` (пользователи, эталоны, выпуск пакета), `controller` (журнал),
`operator` (прогоны) — [OtkRoles](ARDU_OTK.Shared/Security/OtkRoles.cs).

### Администратору

На компьютере администратора в `%LOCALAPPDATA%\ARDU_OTK.Keys` лежат ключ
подписи и токен GitHub. Оба зашифрованы DPAPI под учётной записью Windows.

- **Токен** — fine-grained, доступ только к `ARDU_OTK.Network`, право
  Contents: Read and write. Задаётся в разделе «Сеть». В программу токен не
  зашивается: установщик лежит в открытых релизах.
- 🔴 **Ключ подписи.** Сразу после заведения сети сохраните его резервную копию:
  «Сеть» → «Сохранить резервную копию ключа…». Храните её отдельно от этого
  компьютера. Утрата ключа означает выпуск новой версии приложения с новым
  открытым ключом.

Порядок работы:

1. Завести или изменить пользователей и эталоны.
2. «Сеть» → «Выпустить пакет сети».
3. Станции примут пакет при следующем входе или по кнопке «Проверить
   обновление пакета».
